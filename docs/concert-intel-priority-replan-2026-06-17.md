## 2. 优先级重排

### 2.1 评估维度与评分规则

| 维度 | 简称 | 评分（1-5） |
|------|------|-------------|
| 数据资产价值贡献 | 价值 | 5=核心资产价值 / 1=锦上添花 |
| 实现成本（反向，越高越易） | 成本 | 5=极低成本 / 1=极高成本 |
| 是否阻塞下游 | 阻塞 | 5=硬阻塞 / 1=无阻塞 |

优先级总分 = 价值 + 成本 + 阻塞（满分 15）

- **P0**：总分 ≥ 11，或为硬卡点解除
- **P1**：总分 8-10
- **P2**：总分 ≤ 7

## 3. 推荐下一步

### 3.1 首推：解除最高卡点 + 验证数据底座（双线并行）

| 行动 | 类型 | 预期收益 |
|------|------|----------|
| **A. 推动 Top 50 去重人审完成 → 触发正式 rededup** | 协调/人工 | 解除 C2+C3 卡点，历史数据治理层从 60% → 75%+，确立数据「唯一性」资产基础 |
| **B. 输出回填前后对比报告** | 工程（低成本） | 验证 715 条回填质量，确立数据底座可信度，为后续所有决策提供可信基线 |

**为什么先做这两件**：
- A 是唯一硬卡点的解除——所有下游「基于干净历史数据」的工作都依赖它。工程侧成本极低（去重候选报告已可用），核心是降低单条人审成本并推动用户完成 47 个 review。
- B 成本极低、价值极高、阻塞下游——715 条回填已跑但从未验证，不输出报告就无法确认数据底座是否可信。可与 A 完全并行，互不阻塞。
- 两者完成后，数据资产从「能跑」进入「可信」状态。

### 3.2 次推：把评分层从 65% 推到可用（A/B 完成后立即启动）

| 行动 | 预期收益 |
|------|----------|
| **C. 城市等级配置化** | 评分层关键缺口补齐，为阵容强度规则扫清依赖 |
| **D. 商业评分回归样本扩充 + 评分分布分析** | 用样本驱动规则校准，验证评分是否符合商业直觉，识别虚高分/虚低分 |

**为什么紧接着做**：
- 评分层 65% 是最薄弱的核心层，而评分是数据资产的商业价值核心。
- C 是 D 和「阵容强度规则」的前置依赖——城市层级不配置化，评分分布分析无法准确归因。
- 两者配合能把评分层从「规则已写但未校准」推进到「规则已校准、分布可解释」。

## 6. 决策建议总结（给主理人）

1. **立即做**：推动 Top 50 去重人审（最高卡点）+ 输出回填对比报告（最低成本最高价值）。两者并行，1 周内可完成。
2. **第 1 周同步启动**：评分回归样本扩充 + 评分分布分析，为第 2 周规则校准提供数据支撑。
3. **第 2 周重点**：城市等级配置化 + 信息缺失/高热度评分规则 + 质量保护网（发布前检查 + 真实 fixtures）。
4. **暂缓**：所有 P2 项（LLM 兜底、多人阵容拆分、调试面板、规则配置外置、评分版本化）——在 P0/P1 稳定前不投入，避免高成本低杠杆工作。
5. **不要忘**：git push 2 个提交到 Gitee（C1），尽快由用户本机执行，消除远程备份中断风险。
